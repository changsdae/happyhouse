## 문제 유형과 기대결과

해당 라운드에 의미 있는 정상·경계·실패 유형을 나눕니다. 원문상 정답이 불분명하면 ‘판정 보류’로 기록하고 질문합니다.

| 번호 | 유형 / 확인할 문제 | 입력·조건 | 기대결과 | 정답 근거 | 실제 결과 | 판정 | 실행 증거 |
|---|---|---|---|---|---|---|---|

번호는 이 문서 안에서 01, 02처럼 간단히 씁니다. 실제 출력에 맞춰 기대결과를 바꾸지 않습니다.

## 서로 다른 근거

- 원문 요구사항과 테스트가 빠짐없이 연결되는지 확인
- 독립 손계산 / 원문 예제 / 별도 규칙 중 적용 가능한 정답 근거
- 일부러 틀린 출력·실패 입력을 별도 fixture에서 주어 검증기가 실패를 잡는지 확인
- 이번 라운드 + 이전 라운드 연결 + 영향받은 기능의 회귀검증
- 최종 사용 흐름을 처음부터 끝까지 실행 (최종 라운드 필수)

동일 프롬프트를 두 번 실행하거나 두 AI가 동의하는 것만으로 독립 검증했다고 쓰지 않습니다. 모든 항목을 기계적으로 강제하지 않고 적용 여부와 이유를 기록합니다.
