## 구현·검증

- [ ] 작은 단위 구현과 자체 테스트
- [ ] 기존 라운드 결과에 연결
- [ ] 계획 개정·실제 코드 기준·실행법을 검증담당에게 인계
- [ ] 독립 검증·실패 수정·영향 기능 회귀검증
- [ ] SUMMARY·PLAN 갱신과 의미 있는 로컬 Git 커밋

검증 판정은 CHECK를 근거로 옮깁니다. 코드나 요구가 바뀌면 관련 과거 통과를 재검증 필요로 표시하고 새 근거를 받습니다.

## 내가 이해할 핵심 — 라운드 종료 때 짧게

- 무엇을 추가했고 실제로 어디서 쓰는가:
- 입력 → 핵심 규칙 → 출력:
- 중요한 선택 이유 / 포기한 점:
- 직접 볼 파일·함수 / 실행 예 하나:
- 실제 실패·수정·남은 한계 / CHECK 근거:

| 확인 항목 | 내 설명 / 예상과 실제 | 보완할 점·근거 | 상태 |
|---|---|---|---|
| 입력에서 결과까지 흐름 | 아직 답하지 않음 | | 내 설명 대기 |
| 선택 이유·실패 조건 | 아직 답하지 않음 | | 내 설명 대기 |

사람이 실제로 설명한 뒤에만 확인 / 보완 필요를 적습니다. 읽었다는 응답만으로 설명 확인을 만들지 않습니다. 기능 완료·이해 확인·실행 승인은 별개입니다. 남은 이해 공백은 [REVIEW](../../docs/REVIEW.md)로 넘깁니다.
