# 전체 시스템 이해와 복습

> 실제 최종 구현을 기준으로 짧게 정리합니다. 사람은 이 문서로 전체 흐름을 다시 따라갑니다. 예상 시험문제나 외울 답안을 만들지 않습니다.

- 작성 상태: 구현 전 / 미작성
- 확인한 코드 기준·작성 시각·작성자: 미확인
- 전체 실행 검증: 미실행
- 내 설명 확인: 내 설명 대기

## 1. 무엇을 만들었나

- 사용자·해결할 문제:
- 실제 구현한 범위 / 제외한 범위:
- 서비스 전체를 한 문장으로:

## 2. 입력 하나가 결과가 되는 과정

실제 입력 예 하나를 고르고, 원본 → 검사 → 핵심 처리 → 결과 표시·저장 순서를 이 서비스에 맞춰 채웁니다. 없는 단계를 억지로 만들지 않습니다.

| 단계 | 들어오는 것 → 하는 일 → 나가는 것 | 실제 코드 위치 |
|---|---|---|

핵심 파일·함수는 필요한 3~5개 정도로 추립니다. 위치·호출 흐름은 최종 코드와 대조하고, 설명하기 위한 가정이면 따로 표시합니다.

## 3. 왜 이렇게 만들었나

| 중요한 선택·변경 | 선택 이유 / 포기한 점 | 실제 결정 근거 |
|---|---|---|

중요한 2~3개를 먼저 적습니다. WORK의 라운드·대화 번호와 연결하고 폐기한 안은 현재 구현과 구별합니다.

## 4. 무엇으로 확인했고 무엇이 남았나

| 확인할 동작 / 실제 겪은 오류 | 기대 vs 실제 / 수정 이유 | 검증 근거·한계 |
|---|---|---|

코드·요구가 변경된 뒤 재검증하지 못했다면 명시합니다. 테스트 개수만으로 안전하다고 결론 내리지 않습니다.

## 5. 내가 직접 따라 실행하기

- 실행 준비 / 실제 명령:
- 정상 입력 하나: 입력 → 내가 예상한 결과 → 실제 결과 → 근거
- 실패 입력 하나: 입력 → 내가 예상한 반응 → 실제 반응 → 근거
- 재현에 필요한 데이터·환경 / 알려진 제약:

예상값은 사람이 먼저 말하게 합니다. 실행하지 않은 경우 미실행으로 남깁니다. 실제 입력과 결과는 CHECK·로그로 연결합니다.

## 6. 문서를 잠깐 덮고 내 말로 설명하기

| 확인할 내용 | 내 설명 요약 | 보완할 곳 | 상태 |
|---|---|---|---|
| 누가 무엇을 입력하면 어떤 과정을 거쳐 결과를 받는가 | 아직 답하지 않음 | | 내 설명 대기 |
| 중요한 선택의 이유와 포기한 점 | 아직 답하지 않음 | | 내 설명 대기 |
| 실패할 조건·검증 근거·남은 한계 | 아직 답하지 않음 | | 내 설명 대기 |

AI 설명을 읽었다는 사실과 직접 설명해서 확인한 사실을 구별합니다. 모르는 부분은 관련 WORK·코드·CHECK로 돌아가서 확인합니다.

## 남은 이해 공백과 다음에 볼 곳

- 라운드 / 이해하지 못한 것 / 다시 볼 파일·대화·실행:

이 문서를 AI 사용이 허용된 시간에 준비·복습합니다. 후속 단계에서 문서를 열 수 있는지는 실제 시험 안내를 따릅니다.
