# 현재 인계와 재개

작업 위치는 Workspace, 하네스 원본은 `./_harness/happyhouse/`입니다.

## 현재 인계

- 현재 단계 / 라운드: 문제 이해 전 / 미정
- 갱신 시각 / 작성자: 미작성
- 현재 코드 / 마지막 검증 기준: 미작성
- 완료 / 미완료: 미작성
- 유효한 실행 범위 / 승인 근거: 미작성
- 답하거나 결정할 것: 아직 없음
- 다음 행동: 제공 원문 읽기
- 상세 근거: 미작성
- 다른 세션의 작업 / 재현에 필요한 환경: 미작성

상단은 최신 상태로 갱신합니다. 상세 근거에는 현재 WORK 대화 번호와 CHECK 등을 실제 로컬 링크로 연결합니다.
다음 담당자는 코드·기록과 인계의 일치 여부를 확인하고 현재 범위·미완료·다음 행동을 짧게 되짚습니다.

## 인계 이력

| 순번 | 기록 시각 / 작성자 | 바뀐 상태·이유 / 다음 행동 | 상세 근거 |
|---|---|---|---|

001부터 라운드 종료·중요 변경·작업자 교체 때만 한 줄씩 누적합니다. 매 대화마다 추가하지 않습니다.
대화·결정·검증 전문은 WORK/CHECK/runs에 보존합니다. 이전 최신 상태는 의미 있는 Git 커밋으로 남깁니다.

## 주담당에게

```text
./_harness/happyhouse/AGENTS.md와 ./_harness/happyhouse/roles/MAIN.md를 명시적으로 읽어줘.
이 문서의 현재 인계와 Workspace 기존 지침을 확인한 뒤 docs/PLAN.md, 현재 works/Rn/WORK.md의
상단 상태와 마지막 인계, 해당 validation/Rn/CHECK.md를 읽고 재개해줘.
완료/미완료, 열린 질문, 현재 승인 범위, 다음 행동을 먼저 짧게 정리해줘.
최신 요약과 관련 대화 번호부터 읽고, 근거가 부족하거나 충돌하면 과거 기록을 더 읽어줘.
인계와 실제 코드·검증 기준이 다르면 먼저 차이를 확인해줘.
이해 복습 단계라면 docs/REVIEW.md의 미확인 항목도 읽어줘.
```

## 검증담당에게

```text
./_harness/happyhouse/AGENTS.md와 ./_harness/happyhouse/roles/VALIDATOR.md를 명시적으로 읽어줘.
문제 원문과 docs/PLAN.md, validation/PLAN_REVIEW.md를 읽어줘.
현재 라운드의 validation/Rn/CHECK.md에서 인계와 실행 근거를 확인해줘.
구현 코드를 보기 전에 독립적으로 검증할 조건과 기대결과부터 정리해줘.
```

`Rn`은 docs/PLAN.md의 현재 라운드로 찾습니다. 사람이 경로를 매번 입력할 필요는 없습니다.
현재 라운드가 없으면 문제 이해/계획 단계부터 이어갑니다. `/clear`는 필수가 아닙니다.
새 대화를 시작하기 전 주담당은 WORK.md 마지막 인계, 검증담당은 CHECK.md 마지막 인계를 갱신합니다.
주담당은 검증담당의 인계를 받아 이 문서의 현재 인계와 짧은 이력도 갱신합니다. 상대 세션의 변경은 필요할 때 다시 읽습니다.
